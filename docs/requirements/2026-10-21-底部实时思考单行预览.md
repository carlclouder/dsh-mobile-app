# 底部实时思考单行预览

日期：2026-10-21。状态：已实现，175项测试及双包构建通过，核心设备场景已验证。基线：06066db。分支：codex/live-thinking-preview。
用户已要求本会话免审批，界面验证沿用 GIF 规则。

## 1. 需求确认

用户希望 App 像 WebUI 一样，在思考时让底部文字快速单行滚动。
我按现有 WebUI 的行为理解：显示正在生成的思考末行，随真实内容更新向左推进，点击可展开全文。保留历史思考的折叠方式。此解释沿用本项目已有 ThinkingStreamRow 和历史方案，未引入固定假文案轮播。

## 2. 范围

本次只补底部预览的实时来源和页面接线，复用已有单行滚动组件。
不改变消息发送、排队、审批、提问、通知或历史消息合并逻辑；这些路径已有独立实现，本次没有修改需要。

## 3. 必要延拓

打开正在思考的会话要能恢复当前预览；断线、停止、完成、换地址和下一步开始时不能继续显示旧思考。
新流不受支持时保留原有状态提示与历史轮询；离开页面后取消订阅。点击预览展开全文，下一次模型尝试重置展开状态。列表定位须把新增预览算作真正尾项；收到运行结束状态后补一次历史对账，避免轮询取消时遗漏最终回复。真实验收发现长思考期间列表请求会超时，因此有效实时生成结束及重连快照也须调度原请求闸门补读历史，不能只依赖曾看到 running=true。

## 4. 架构

新增纯 Kotlin 思考预览状态归约器，负责官方快照和增量的顺序校验。
新增只读会话跟随器，负责 WebSocket、换代、重连及 80ms 发布节流。
页面 ViewModel 持有跟随器，界面复用 ThinkingStreamRow。实时内容不写 sessionEvents，避免与历史轮询产生重复消息和统计。

## 5. 模块关系

DshApiClient 现有 openEventStream 提供认证和套接字登记；DshThinkingStream 打开 session/follow；ThinkingPreviewState 消费帧；ViewModel 暴露预览；ConversationActivity 在底部显示。
文件分别放 model/、service/、ui/ 现有目录，并登记架构索引。

## 6. 解耦

预览状态不依赖 Android 或消息列表；网络层不调用页面组件。
预览公开 key、content，key 标识当前尝试，content 只包含当前仍在生成的思考正文。页面只读取 StateFlow，不接触远端帧结构。

## 7. 内聚

尝试、块索引和修订号归状态归约器；套接字和重连归跟随器；生命周期归 ViewModel；裁剪、贴尾、扫光和展开归已有界面组件。

## 8. 流程

1. 打开会话即订阅 session/follow，显式 assistantStream=true，仅当前页面持有。
2. 从 snapshot.assistantStream 恢复 activeAttempt 的紧凑流；没有 activeAttempt 就清空。
3. 新 start 清空旧尝试；chunk 按 attemptId、revision 和原始 index 逐个消费；80ms 最多发布一次预览。
4. 显示当前尾部 reasoning 块；正文或工具块开始后清空底部思考预览。
5. end 无论 committed 或 abandoned 均清空。会话运行状态由 true 变 false 时通过既有单请求闸门补最后一次历史对账；不改消息合并算法。有效 assistant-stream.end（committed/abandoned）及有效 snapshot 也调度一次原历史补读，覆盖未见运行状态变化、断线错过结束的情况；end 仅表示一次生成结束，不改整个回合运行标志。
6. 断线/换地址立即清空，旧回调不能写新连接；退避重连后重新取快照。
7. 关闭 ViewModel 时关闭本订阅；不关闭全局 API 客户端或交互流。

## 9. 状态与算法

修订号 revision 表示 assistantStream 的连续变化，frame.index 表示本次尝试的原始片段序号；chunk.index 是内容块索引，三者不能混用。
快照紧凑记录的 reasoning-chunks/text-chunks 按 texts 恢复，tool-call-chunks 按 args 恢复；raw chunk 计1个，压缩段按成员数计数，总数须与 nextIndex 一致，不能使用 records.size。内容按块索引区分，block-end 携完整 block 时替换而非重复追加。正文与工具等记录必须更新当前尾块，避免旧思考被误认成正在生成。
索引/修订缺口或畸形关键帧不拼接猜测，清空并重新请求快照；重复帧不重复追加。大正文只在 80ms 发布时生成展示字符串，避免每个片段重建整条消息列表。

## 10. 接口与源码依据

物理路径为 /api/remote.mux。开流：type=open，endpoint=session/follow，payload.args.request={address:{kind:"session",sessionId},assistantStream:true,maxMessages:1}。
快照含 assistantStream={revision,activeAttempt?:{attemptId,startedAfterSeq,turn,step,nextIndex,stream}}。
实时项为 {type:"assistant-stream",frame:{type:"start"|"chunk"|"end",attemptId,revision,...}}。精确压缩记录规则由官方定义核对后实现，禁止按文本字段名猜测。

官方安装包依据：dsh-api-session-controller/lib/typert.host.js:203–222、384–423、1044–1066；lib/index.js:1239–1309、1480–1489。
WebUI 只将当前尝试最后一块 reasoning 标为 running：dsh-client-ui-chat/lib/client.js:5896–5925。
App 现状证据：ConversationActivity 的 ThinkingIndicator 为固定文案；旧 CollapsibleThinking 仅 STREAMING_KEY 启用单行；EventStreamService 已停止旧事件订阅；ViewModel 的历史对账过滤片段，故无新实时思考进入该组件。

## 12. 实际场景

App 发出问题后，底部从等待提示变为最新思考末行；长句向左推进，换行时切到最新行。用户可以展开查看这次思考全文。
进入其他端已经在运行的会话时，快照恢复当前思考。新尝试、断网或结束时撤掉旧预览；历史消息继续通过既有路径显示。
用户向上翻阅不被高频预览强行拉回；跳底和贴底判断计入预览尾项，跳底按钮按实际剩余滚动距离显示；点跳到底部恢复跟随。思考为空时不编造内容。
